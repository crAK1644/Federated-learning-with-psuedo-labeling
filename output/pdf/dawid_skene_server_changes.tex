\section{Purpose}

This document explains one contained implementation decision: use the Dawid-Skene algorithm on the
central server to combine the hard labels that clients already upload. It is written so reviewers can
understand the logic, the exact system boundary, and the controlled test before approving the work.
\textbf{Status:} the logic is under review; it is not an implemented or validated result, and no
performance improvement is claimed. Revision 2 adds the measured size of the problem
(Section~\ref{sec:evidence}), taken from artifacts already on disk, plus the safeguards and staging
the code review found missing.

\decisionbox{\textbf{Approval target.} Approve a server-only implementation and a staged experiment.
Majority voting remains available and remains the fallback. No client model, soft label, posterior,
confusion matrix, or reliability score is transmitted.}

\section{Current decision and changed decision}

Each client predicts a class for every sample in the same shared open dataset. A client sends a class
number from 0 to 10, or \code{-1} when it abstains. The server must turn these separate opinions into
one hard global label per sample.

\begin{table}[H]
\centering
\begin{tabularx}{\textwidth}{L{0.24\textwidth}YY}
\toprule
 & \textbf{Current: majority vote} & \textbf{With Dawid-Skene} \\
\midrule
Question asked & Which class received the most votes? & Which hidden class best explains the full
pattern of agreements and disagreements? \\
Client treatment & Every accepted label counts equally. & Each client's class-specific confusion
pattern is estimated from the round's label table. \\
Output & One hard label and one validity flag per sample. & The same hard label and validity flag. \\
Failure behavior & Deterministic majority result. & Deterministic majority result is used if the fit
is unsupported, invalid, or does not converge. \\
\bottomrule
\end{tabularx}
\end{table}

\subsection{Why it differs from majority}

Clients do not necessarily make the same kind of mistake. One may distinguish classes 2 and 3 well
but confuse classes 7 and 8; another may show the opposite pattern. Majority voting ignores that
structure. Dawid-Skene estimates it and uses it when choosing the label. It can therefore choose a
different class from majority when the disagreement pattern supports another class.

This does \textbf{not} make consensus equal to ground truth. Similar client models can make the same
mistake together, and on this dataset they measurably do: most current label errors are not close
votes but landslides in which nearly every client agrees on the wrong class
(Section~\ref{sec:evidence}). Overturning
those requires the estimated confusion structure to be trusted precisely where the model's
independence assumption is weakest. That is the main scientific risk of the experiment, and it is
stated here rather than discovered later. The result must be checked offline against sealed labels
after a run; sealed labels must never enter live aggregation or training.

\subsection{Strict scope}

\begin{itemize}
  \item \textbf{Clients stay unchanged:} training, prediction, discriminator filtering, abstention,
        hard-label upload, and distillation are untouched.
  \item \textbf{The wire contract stays unchanged:} clients upload the existing hard-label vector;
        the server returns only \code{global\_labels} and \code{valid\_mask}.
  \item \textbf{Only the server decision changes:} Dawid-Skene is inserted where the server currently
        combines validated hard-label proposals.
\end{itemize}

The \textbf{reachable ceiling} is the share of samples whose true class was proposed by at least one
client. No vote-based aggregator, Dawid-Skene included, can exceed it.

\begin{enumerate}
  \item \textbf{Label quality is the binding constraint.} The server model finishes the run at 0.7335
        accuracy while the labels it distils from are 0.739 correct. The model has already saturated
        to its supervision, so aggregation is the right place to intervene.
  \item \textbf{The headroom is 0.739 to 0.997.} For almost every sample somebody votes the true class
        and is outvoted. This is the regime Dawid-Skene is designed for.
  \item \textbf{The headroom sits where the method is weakest.} Only 14\% of final-round errors are
        near-ties. Three classes are absorbed wholesale by a confident majority: class 4
        (\code{gafgyt.tcp}) recall \textbf{0.000} into class 5, class 2 (\code{gafgyt.junk}) 0.120 into
        class 1, and class 6 (\code{mirai.ack}) 0.335 into class 9. Every other class is above 0.89.
        Success therefore depends on the estimated confusion matrices identifying a correct minority
        against a correlated majority.
\end{enumerate}

\decisionbox{\textbf{What this changes for the reviewer.} The improvement to look for is not a small
tie-breaking gain. It is whether the three collapsed classes are recovered. Worst-class recall and
per-class recall of the \emph{aggregated labels} are therefore primary outcomes, not secondary ones:
macro-F1 alone can move without any collapsed class recovering.}

\textit{Caveat.} The recorded run's dataset manifest hash (\code{f529785f\ldots}) differs from the
local one (\code{54023e3e\ldots}): same seed, split counts, and feature schema, but 96 differing file
checksums, so the two hosts prepared data under different library versions. Row alignment is
empirically certain --- chance accuracy under misalignment is 0.092 against 0.739 measured, with
coherent per-class structure --- but confirmatory numbers must be regenerated on the experiment host
against its own manifest. See the host and manifest control in Section~\ref{sec:test}.

\section{Algorithm logic}

Let $Y_{ji}$ be client $j$'s label for shared sample $i$. Legal observations are classes
$0,\ldots,C-1$; $Y_{ji}=-1$ is missing. The server estimates:

\begin{itemize}
  \item $P(z_i=c)$: the posterior probability that sample $i$ belongs to hidden class $c$;
  \item $\pi_c$: the estimated frequency of class $c$; and
  \item $M_j[c,k]$: how often client $j$ reports class $k$ when the hidden class is $c$.
\end{itemize}

\begin{enumerate}
  \item \textbf{Validate and align.} Check sender identity, manifest, vector shape, legal values, and
        duplicates. Sort accepted senders so input order cannot change the answer. Identical retries
        count once; conflicting replies from one sender are rejected for that round.
  \item \textbf{Build the matrix.} Put accepted vectors into $Y[\text{client},\text{sample}]$ and treat
        every \code{-1} as missing evidence.
  \item \textbf{Initialize.} Start sample probabilities from smoothed vote proportions. Smoothing
        prevents an unseen class from receiving an irreversible probability of zero.
  \item \textbf{M-step: reconsider clients.} Use the current sample probabilities to update the
        class prior and every supported row of every client's confusion matrix. Pseudocounts prevent
        zero rows and stabilize sparse classes.
  \item \textbf{E-step: reconsider samples.} For every usable sample and class, combine the updated
        class prior with the observed clients' current confusion probabilities:
        \[
        P(z_i=c\mid Y_{\cdot i}) \propto \pi_c
        \prod_{j:Y_{ji}\neq -1} M_j[c,Y_{ji}].
        \]
        The implementation performs this calculation in log space to avoid numerical underflow.
  \item \textbf{Repeat.} Alternate M and E until the regularized objective changes by no more than
        the tolerance, or the iteration ceiling is reached.
  \item \textbf{Return a hard decision.} For every supported sample, choose the class with the largest
        posterior probability. Exact ties use the lowest class index, matching deterministic behavior.
\end{enumerate}

\subsection{Operational pseudocode}

\begin{center}
\fcolorbox{RuleGray}{SoftGray}{\begin{minipage}{0.94\textwidth}\ttfamily\small
collect and validate existing client hard-label vectors\par
compute deterministic majority once for fallback\par
if there is insufficient usable evidence: return majority\par
initialize posterior probabilities from smoothed votes\par
repeat M-step then E-step in float64 log space\par
\quad if any value is invalid or the objective falls beyond numerical tolerance: return majority\par
\quad if converged: return hard MAP labels and the existing valid mask\par
if the iteration ceiling is reached without convergence: return majority\par
record mode, support, iterations, likelihood, objective, timing, disagreement, and fallback reason
\end{minipage}}
\end{center}

\decisionbox{\textbf{Important interpretation.} The estimated confusion matrices are round-specific
aggregation variables, not permanent client reputation scores. The first implementation starts cold
in every round; warm start is disabled.}

\section{Implementation and safety contract}
\begingroup
\small
\renewcommand{\arraystretch}{1.05}

The insertion point is \code{SSFLStrategy.aggregate\_train} in
\code{src/ssfl/strategies/ssfl.py}. After the server validates and de-duplicates client proposals, the
current hard-label branch calls majority aggregation. The new server selector chooses majority,
shadow, or active Dawid-Skene and always returns the existing aggregation result shape. The existing
soft-probability research path is separate and is not changed by this work.

\begin{table}[H]
\centering
\begin{tabularx}{\textwidth}{L{0.25\textwidth}Y}
\toprule
\textbf{Server area} & \textbf{Required change} \\
\midrule
Estimator & Add a self-contained hard-label Dawid-Skene calculation: initialization, E-step,
M-step, stopping checks, a success/failure result, and aggregate diagnostics. \\
Aggregation selector & Build the stable client-by-sample matrix; preserve the current majority
function and lowest-class tie-break; select majority, shadow, or active mode. When no valid proposal
exists, preserve the current outer control flow and do not invoke Dawid-Skene. \\
Configuration & Add validated settings, include them in the run identity, and reject unsupported
warm start. Majority remains the default. \\
Diagnostics and reports & Record convergence, fallback, disagreement, support, time, and memory;
keep results separated by aggregation mode. Client confusion matrices remain restricted diagnostics. \\
\bottomrule
\end{tabularx}
\end{table}

\subsection{Non-negotiable safeguards}

\begin{itemize}
  \item No new Dawid-Skene field may cross the network. Shadow mode must broadcast the same logical
        labels and mask as majority for the same valid unique-sender submissions.
  \item Insufficient support, non-finite values, objective failure, or reaching the cap without
        convergence must use majority from the same validated and de-duplicated proposal batch.
  \item Raw client-by-sample matrices are off by default; any temporary audit is restricted,
        pseudonymized, owner-controlled, and deleted after settings are locked.
  \item \textbf{Shadow mode is a control only if it is bit-identical.} Dawid-Skene must consume no
        random state, so a shadow run and a majority run at the same seed must produce identical
        recorded metrics, not merely the same broadcast labels. This is asserted as a gate; without
        it the shadow arm is not a control.
  \item \textbf{Hidden-class permutation is detected, not assumed away.} After convergence, require
        diagonal dominance across a preregistered share of supported client-class pairs and agreement
        with majority above a preregistered floor. Violation returns majority and logs the reason.
  \item \textbf{Sealed labels are read, never written.} The open split has no label file on disk; the
        offline evaluator reconstructs the labels from the existing preparation audit table. Writing a
        label file into the prepared dataset would change its manifest hash, and therefore every run
        identity, breaking comparability with runs already recorded.
\end{itemize}

\subsection{What will be measured}

\begin{itemize}
  \item \textbf{Primary model outcomes:} mean server macro-F1 and accuracy over the final 10 rounds.
  \item \textbf{Offline label quality:} accuracy, macro-F1, per-class recall, corrected errors,
        introduced errors, matched coverage, posterior calibration, and class balance.
  \item \textbf{Recovery of the collapsed classes} \textit{(added in revision 2)}: per-class recall of
        the aggregated labels for classes 2, 4, and 6, reported against the reachable ceiling rather
        than against majority alone. The ceiling is the honest denominator for any claimed gain.
  \item \textbf{Estimability} \textit{(added in revision 2)}: per-client annotation counts per
        scenario, the accepted risk carried by the annotation floor of 1.
  \item \textbf{Safety:} worst-class recall, new class collapse, fallback rate, permutation-check
        failures, convergence, invalid values, and whether gains come mainly from rejecting samples.
  \item \textbf{Engineering:} server aggregation time, peak memory, audit size, resume behavior, and
        proof that tensor names, shapes, types, and logical network byte counts are unchanged.
  \item \textbf{Provenance:} dataset manifest hash and host, reported next to every arm.
\end{itemize}

Results are paired within scenario and seed, and scenarios are reported separately. Items and rounds
are repeated observations, not independent experiments. Every assigned active round remains in the
active arm even if it falls back to majority. Settings are locked before the matched comparison and
are never tuned using sealed test labels.

\subsection{Stop conditions}

Stop and inspect before continuing if probabilities are invalid, the permutation check fires
repeatedly, a class collapses, convergence repeatedly fails, fallback becomes frequent, runtime or
memory grows materially, any new client payload appears, or matched results are worse. All outcomes
are reported; failed runs are not replaced with better seeds. A negative result --- Dawid-Skene
matching majority and leaving classes 2, 4, and 6 collapsed --- is a reportable finding about
correlated client error on this dataset, not a failed experiment.
